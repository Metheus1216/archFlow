#  ArchFlow MVP (最小可行性产品) 需求边界

## 一、 MVP 核心目标

跑通“输入 Idea → AI 追问约束 → 生成架构图 → 用户微调 → 保存为资产”的端到端单机闭环。
**核心原则：** 追求极致的流程闭环与代码透明度，绝不提前做高并发、多端协作等非核心功能。

------

## 二、  MVP 必须包含的功能 (Must Have)

### 1. 用户认证 (Auth)

- 支持邮箱 + 密码注册与登录。
- 基于 Redis 的双 Token (Access + Refresh) 无感刷新机制。
- 登录状态失效时，前端能自动拦截并跳转回登录页。

### 2. 侧边栏与项目管理 (Sidebar & Projects)

- 支持“新建项目”并在左侧树形菜单中展示。
- 空状态处理：当用户没有任何项目时，主界面显示全屏引导页，而不是空白的三栏布局。
- 支持展示历史会话列表，并高亮当前选中的会话。

### 3. AI 对话与约束收集 (Agent Chat)

- 支持原生 SSE 流式输出（打字机效果）。
- **约束卡片**：AI 能抛出结构化的单选/多选卡片（如团队规模），用户作答后卡片原地变灰，Agent 继续推理。
- **状态提示**：AI 思考过程中，能展示“正在查知识库”、“正在生成图”等阶段性提示。

### 4. 架构图画布 (React Flow Canvas)

- 支持渲染大模型返回的节点和连线。
- 支持用户手动拖拽节点、缩放画布。
- 支持点击“自动布局”，使用 Dagre 算法瞬间重排节点。
- **防抖保存与乐观锁**：用户拖拽停顿 3 秒后自动保存草稿。如果多端同时修改，能通过版本号检测冲突并提示（不覆盖数据）。

### 5. 知识库检索 (Basic RAG)

- 支持上传并解析 `.md` / `.txt` 文本与图片。
- PDF / DOCX 仅上传存储、不解析，不可被 AI 引用。
- 文件存放在 MinIO，文本内容被切片存入 PostgreSQL (`pgvector`)。
- AI 对话时，能基于已解析（`ready`）的文件内容进行回答。

### 6. 资产固化与历史回溯 (Assets & Fork)

- **保存资产**：将满意的画布保存为“架构资产”，存入侧边栏。
- **恢复快照**：点击历史消息的“恢复快照”，右侧画布瞬间回到当时的版本。
- **物理复制分支**：基于某条历史消息“开启新对话”，系统复制该消息及之前的记录，保证上下文绝对隔离。

------

## 三、  MVP 明确不做的功能 (Won't Have)

为了防止技术发散，以下功能**严禁**在 MVP 代码库中出现：

1. **PDF / DOCX 解析**：只上传存储，不做解析（避免引入 Python/Go 或重型解析库）。
2. **复杂的文档解析微服务**：所有文本切片逻辑用 Node.js 原地解决，不引入 Python/Go 微服务。
3. **异步消息队列**：不使用 BullMQ / RabbitMQ。大模型推流直接用 Node.js 异步长连接处理。
4. **多端实时协作**：不使用 WebSocket 进行画布同步。暂不做“多人同时编辑”。
5. **多人权限体系**：每个项目只有一个所有者（Owner），不建 `project_members` 表。
6. **复杂 Agent 编排**：不引入 LangChain / LangGraph。采用手写状态机 + 原生 Function Calling。
7. **移动端深度适配**：优先保证桌面端宽屏（Web）体验。

> post-MVP 的 RabbitMQ + Go 文档解析服务规划见 [`架构规划.md`](./架构规划.md)；不改变本文的 MVP 边界，也不意味着现在可以写相关代码。

## 四、  验收标准 (Acceptance Criteria)

当以下场景全部顺畅无 Bug 时，MVP 正式宣告完成：

- □ 

  新用户注册登录后，能看到全屏引导页，点击按钮能成功创建第一个项目。

- □ 

  用户能发消息，大模型能流式输出文字，并抛出追问卡片。

- □ 

  用户回答卡片后，大模型能生成完整的架构图渲染在右侧画布上。

- □ 

  用户能拖拽节点调整布局，并且刷新页面后进度不丢失。

- □ 

  用户点击“保存资产”，左侧列表能立刻显示这个图。

- □ 

  用户基于历史消息点“恢复快照”，右侧画布能精准还原。

- □ 

  用户上传 `需求文档.md`，再次对话时，AI 能基于文档里的内容给出回答。
