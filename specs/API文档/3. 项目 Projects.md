# 3. 项目与侧栏目录

> 当前只有开发模拟操作，真实接口待实现。请求与响应复用 `project.schema.ts`，分页复用公共定义。

## 3.1 获取项目目录

```http
GET /api/v1/projects?limit=20&cursor=xxx
```

返回 `200` 和 `PageSchema(ProjectNode)`，供侧栏一次读取项目及文件、资产、会话的简要信息。项目列表分页，嵌套数组数量由 `ProjectNode` 控制，不在此重复上限。

`lastActiveConversationId` 是该项目下最近活跃会话的外部 ID，没有会话则为 `null`。服务端查询派生，数据库没有同名列。客户端不能只在已加载的一页嵌套会话里寻找“全项目最近会话”。

各嵌套列表按最近更新优先稳定排序，超出首批数量后使用对应资源的列表接口。文件和资产简要信息不含完整内容或图。没有项目时返回空 `items`，由前端显示创建引导。

## 3.2 创建项目

```http
POST /api/v1/projects
Idempotency-Key: <本次操作标识>
```

请求使用 `CreateProjectInput`：

```json
{ "name": "活动报名系统", "description": "学校社团活动报名" }
```

项目允许重名。返回 `201` 和 `Project`，不自动创建示例文件、示例资产或会话。前端再调用创建会话接口；第二步失败时只重试建会话，项目不重复创建。

## 3.3 查询项目详情

```http
GET /api/v1/projects/:projectId
```

返回 `200` 与 `Project`，不含侧栏嵌套数组。不存在或不属于当前用户都返回 `404 PROJECT_NOT_FOUND`。

## 3.4 更新项目

```http
PATCH /api/v1/projects/:projectId
```

请求使用 `UpdateProjectInput`，只提交需要修改的字段且至少一项。返回更新后的 `Project`。

## 3.5 删除项目

```http
DELETE /api/v1/projects/:projectId
```

成功返回 204 与 `X-Trace-Id`。现有数据库设计级联删除关联会话、消息、任务、条件状态、文件、片段与资产，没有回收站或“30 天恢复”能力。

接口实现还要清理 MinIO 对象和协调正在执行的任务，失败补偿见[Q-08](../待确认问题.md#q-08-删除行为与对象存储清理)。前端删除前明确告知影响范围，不以模拟文件里的数组删除作为真实链路验收。
