# 数据流

> 约定：所有业务接口前缀 `/api/v1`；路径参数统一用 `:conversationId` / `:messageId` 这类命名（对外字段名是 `id`，不是 `uuid`）。字段长度与格式约束以 §10 Zod 模型为准。

## 流 1：认证与无感刷新流 (Auth & Token)

目标：安全登录，静默续期。

1. 登录：前端 `POST /api/v1/auth/login` → 后端校验通过 → `accessToken` 放在响应体，`refreshToken` 通过 `Set-Cookie` 写入 httpOnly Cookie；Redis 只存 refreshToken 的 hash 与 TTL。
2. 日常请求：前端拦截器自动加 `Authorization: Bearer <accessToken>`。
3. 无感刷新：`accessToken` 过期返回 `401 TOKEN_EXPIRED`。前端拦截器挂起请求并做并发去重，调 `POST /api/v1/auth/refresh`（Cookie 自动携带，无请求体）→ 后端轮转 refreshToken、签发新 accessToken → 重发刚才挂起的请求一次。
4. 刷新失败（`REFRESH_INVALID`）：清本地态，跳登录。

## 流 2：冷启动与空状态 (Cold Start)

目标：极速渲染，新用户引导。

1. 当前用户：`GET /api/v1/auth/me`，401 则跳登录。
2. 拉取骨架：`GET /api/v1/projects?limit=20`，返回 `{ items, nextCursor, hasMore }`。
3. 分支渲染：
   - `items` 为空：全屏渲染引导页（“+ 创建你的第一个项目”大按钮）。
   - 有项目：取 `items[0].lastActiveConversationId`，前端不再自己遍历会话找最新。
4. 加载会话：`GET /api/v1/conversations/:conversationId`（元信息 + `draftGraph`，不含消息）。
5. 加载消息：`GET /api/v1/conversations/:conversationId/messages?limit=30&direction=backward`。

## 流 3：新建项目与会话初始化

场景：在引导页或侧边栏点击“新建项目”。

1. 建项目：前端弹窗输入名字，`POST /api/v1/projects`（带 `Idempotency-Key`）→ 返回 `id`。
2. 页面切换：前端 Zustand 更新，引导页消失，三栏工作台出现。
3. 建首会话：前端自动调 `POST /api/v1/projects/:projectId/conversations` 创建新会话，高亮该会话，画布清空。

## 流 4：核心对话与 SSE 流式推演 (Agent Run)

目标：发消息、大模型推流、画布更新、任务可中断、断线可恢复。

1. 前置校验：前端若有未保存的画布草稿，先 `PUT /api/v1/conversations/:conversationId/draft`（带 `baseVersion`）落库。
2. 受理：`POST /api/v1/conversations/:conversationId/messages`（带 `Idempotency-Key`）→ `202`，拿 `runId` / `userMessageId` / `assistantMessageId` / `streamUrl`，`status = queued`。
3. 建立流：用 `fetchEventSource(streamUrl, { headers: { Authorization }, openWhenHidden: true })`（`@microsoft/fetch-event-source`）消费 SSE，**不能用原生 EventSource**（无法带 Authorization 头）。
4. 首帧握手：收到 `run-start`（含 `runId`、`assistantMessageId`、`traceId`），建立 AI 空气泡，显示“停止生成”按钮。
5. 状态流转：后端推 `status`（`thinking` → `searching_knowledge` → `drafting_graph` → `finalizing`），前端更新提示文字。
6. 文本与图推流：
   - `text-delta`：前端追加文字（打字机）；服务端同时把累积文本按节流写入 `messages.content`（约 1 秒或每 200 token），作为断线恢复的权威数据。
   - `graph`：前端整体替换画布（`replace: true`，以最后一帧为准）。
   - 其他：`citation` 渲染来源角标，`title` 更新侧边栏，`usage` 埋点。
7. 结束收尾：后端推 `done`，再发 `[DONE]`；前端停止解析，并重新拉一次 `GET /api/v1/conversations/:conversationId/messages` 做最终校准。
8. 兜底与重连：
   - 断线不终止 run：`GET /stream` 断开只停止推送，Agent 继续生成并写缓冲。
   - 重连：`GET /api/v1/runs/:runId/stream`，带 `Last-Event-ID` 续传；缓冲失效时服务端按 `runId` 查 `runs` / `messages` 合成快照重放；`409 RUN_NOT_RESUMABLE` 仅用于数据异常。
   - 轮询：`GET /api/v1/runs/:runId` 查终态；连续重连失败 3 次后降级为轮询。
   - 取消：`POST /api/v1/runs/:runId/cancel` → `202`；终态 `canceled` 通过流或轮询获得。

## 流 5：约束卡片交互流 (Constraint Cards)

目标：无刷新作答，UI 状态原地同步。

1. 下发卡片：SSE 推 `constraint-card`，前端渲染单选 / 多选 / 输入框（`status = pending`）。
2. 用户作答：`POST /api/v1/conversations/:conversationId/messages/:messageId/answer`（带 `Idempotency-Key`）→ `202`，拿新 `runId`（`status = queued`）。
3. 重复提交：同一卡片再次提交返回 `200`，重放首次的 run 结果，不会重复推理。
4. 状态更新：前端收到 `202` 后先乐观置灰；后端立即把 `status` 改为 `answered` 并写入 `answer`，之后推 `card-updated`，流结束后前端重新拉消息列表校准。
5. 刷新不丢：卡片持久化在 `message.metadata.card`，`GET /messages` 会带回；`pending` 卡片仍可回答。

## 流 6：画布编辑与乐观锁防抖 (Draft Save)

目标：防止多端覆盖，实现自动保存。

1. 高频操作：用户拖拽节点，前端只更新 Zustand，不触发网络请求。
2. 防抖保存：停手 **3 秒**后，前端调 `PUT /api/v1/conversations/:conversationId/draft`，传 `{ graph, baseVersion }`。
3. 后端校验：`baseVersion` 一致则存库、版本号 +1，返回 `{ draftVersion, updatedAt }`；不一致返回 `409 DRAFT_VERSION_CONFLICT`，`data.currentVersion` 给出服务端最新版本。
4. 图超过 512KB 或深于 6 层：草稿返回 `413 GRAPH_TOO_LARGE`，资产返回 `422 GRAPH_INVALID`。
5. 服务端对单会话限流建议 ≤ 2 次/秒，超出 `429`。

## 流 7：资产固化与懒加载 (Assets)

目标：导出成果，节省带宽。

1. 保存资产：点画布“导出 → 保存资产”，`POST /api/v1/projects/:projectId/assets`（带 `Idempotency-Key`），左侧列表刷新。
2. 列表查询：`GET /api/v1/projects/:projectId/assets?limit=20&cursor=...`，不返回 `graph`。
3. 详情懒加载：`GET /api/v1/projects/:projectId/assets/:assetId?includeGraph=true`，返回 `graph` 并渲染到画布；`includeGraph=false` 只返回元信息。

## 流 8：历史分支与快照回溯 (Fork & Snapshot)

目标：像 Git 一样管理架构版本。

1. 开新分支（Fork）：用户在某条消息点“开启新分支”，`POST /api/v1/conversations/:conversationId/fork`（带 `Idempotency-Key`，传 `sourceMessageId`）。后端物理复制该消息及之前的记录，并带入当时的图快照，返回新会话（`ForkResult`），前端跳转。
2. 恢复快照：用户在某条历史消息点“恢复此时画布”，前端直接提取该条消息的 `graphSnapshot` 覆盖本地画布，并按流 6 触发防抖保存。

## 流 9：文件上传与解析 (Files)

目标：text / image 可解析并进入 RAG；pdf / docx 只存不解析。

1. 上传：`POST /api/v1/projects/:projectId/files`（`multipart/form-data`，字段 `file`）→ `201`，返回 `FileMeta`。
2. text / image：`status = processing`，前端轮询 `GET /api/v1/projects/:projectId/files/status?ids=fil_1,fil_2`（2s 起步指数退避，上限 60s）→ `ready` 可被 Agent 引用，或 `failed` 展示 `errorMessage`。
3. pdf / docx：上传后直接 `status = stored`，不解析、不可被 Agent 引用；前端展示「暂不支持解析」，不再轮询。
4. 下载：`GET /api/v1/files/:fileId/content`（鉴权代理，支持 `Range` / `ETag`）。
5. 删除：`DELETE /api/v1/projects/:projectId/files/:fileId`。
