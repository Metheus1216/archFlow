# 1. 全局协议与错误处理

> 本文是目标规范，当前实现差异见[Q-04](../待确认问题.md#q-04-统一错误规则与当前过滤器有差异)。字段规则唯一来源是[共享 Zod](../../packages/shared/src/schemas/)，不是文档中的示例。

## 1.1 基础约定

| 项目       | 约定                                                               |
| ---------- | ------------------------------------------------------------------ |
| 业务前缀   | `/api/v1`；`/health`、`/ready` 使用根路径                          |
| 编码与格式 | UTF-8、JSON；文件上传使用 multipart，下载返回文件内容              |
| 标识       | 对外字段名 `id`，值来自数据库 `uuid`；内部自增主键不返回           |
| 时间       | ISO 8601，包含时区；服务端展示约定为东八区，Zod 也允许其他合法偏移 |
| 字段名     | API 使用 camelCase，数据库使用 snake_case，由服务端显式映射        |
| 空值       | 无对象用 `null`，无列表项用 `[]`；不以空字符串冒充缺失对象         |

`prj_1`、`msg_1` 等是示例简写。客户端把标识和分页游标当作不透明字符串，不解析其内部含义。

## 1.2 认证与刷新

业务请求使用 `Authorization: Bearer <accessToken>`。公开入口为注册、登录、刷新以及健康检查；当前用户和退出接口仍需认证。后续密码重置入口暂不实现。

访问凭证放在前端内存，初始设计有效期 15 分钟；刷新凭证通过 `HttpOnly; Secure; SameSite=Lax; Path=/api/v1/auth` Cookie 下发，初始有效期 30 天，均由服务端配置。Cookie 刷新请求要允许携带凭证；普通 HTTP 本地开发的 Cookie 策略应在 P0-14 明确，不能把生产安全属性无说明地删除。

刷新时替换旧凭证。检测到旧刷新凭证复用，按所属设备会话族吊销，返回 `REFRESH_INVALID`；用户主动选择全部设备退出时再吊销全部会话。Redis 保存哈希、有效期及轮转关系，不保存明文凭证。

| 错误码                                              | 前端处理                                               |
| --------------------------------------------------- | ------------------------------------------------------ |
| `TOKEN_EXPIRED`                                     | 所有并发失败请求共用一次刷新，成功后最多重试原请求一次 |
| `TOKEN_MISSING`、`TOKEN_INVALID`、`REFRESH_INVALID` | 清除本地登录状态，进入登录页                           |
| `INVALID_CREDENTIALS`                               | 登录表单提示邮箱或密码错误，不触发刷新                 |

页面重载后先刷新以恢复内存凭证，再调用 `/auth/me`。页面跳转提示 Cookie 不承担鉴权。凭证不能进入 URL 查询参数、日志或模型输入。

## 1.3 统一响应

普通 JSON 响应使用 `ApiResponseSchema`：

```json
{
  "code": "OK",
  "message": "ok",
  "data": {},
  "traceId": "7f3a1c9e4b2d"
}
```

失败时 `code` 使用 `ERROR_CODES` 大写常量，**`data` 始终为 `null`**。可选 `errors` 由 `FieldError` 定义，可携带字段路径、错误码与提示。`traceId` 用于关联服务端日志，HTTP 状态码同时表达成功或失败。

模块文档展示的响应默认只写 `data` 内容。成功出口仍需要按共享定义校验并映射数据；全局入参管道不会自动校验响应，不能把直接返回实体当作契约校验。

## 1.4 错误示例

```json
{
  "code": "VALIDATION_FAILED",
  "message": "请求参数不合法",
  "data": null,
  "errors": [
    {
      "field": "email",
      "code": "VALIDATION_FAILED",
      "message": "邮箱格式不正确"
    }
  ],
  "traceId": "7f3a1c9e4b2d"
}
```

```json
{
  "code": "CONVERSATION_BUSY",
  "message": "上一条回复还在生成中",
  "data": null,
  "traceId": "7f3a1c9e4b2d"
}
```

草稿版本冲突时，重新获取会话读取最新版本。会话忙时，如果客户端已知任务 ID，可重新查询该任务；本规范不从错误 `data` 返回 `activeRunId` 或 `currentVersion`。新设备发现活跃任务的接口仍需另行定义。

## 1.5 错误码与 HTTP 状态

错误码唯一清单为 [ERROR_CODES](../../packages/shared/src/constants/error-codes.ts)。以下说明目标映射，具体行为还需要接口测试。

| HTTP      | 错误码                                                                                                                                                       | 含义与处理                                                                |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| 400       | `BAD_REQUEST`                                                                                                                                                | 请求协议或语法错误                                                        |
| 422       | `VALIDATION_FAILED`、`MESSAGE_TOO_LONG`                                                                                                                      | 参数不符合定义，按字段提示；当前全局普通 Zod 校验仍返回 400，P0-02 需统一 |
| 401       | `TOKEN_MISSING`、`TOKEN_EXPIRED`、`TOKEN_INVALID`、`REFRESH_INVALID`                                                                                         | 登录凭证问题，见 1.2                                                      |
| 401       | `INVALID_CREDENTIALS`                                                                                                                                        | 登录信息错误                                                              |
| 409       | `EMAIL_TAKEN`                                                                                                                                                | 注册邮箱已占用                                                            |
| 404       | `USER_NOT_FOUND`、`PROJECT_NOT_FOUND`、`CONVERSATION_NOT_FOUND`、`MESSAGE_NOT_FOUND`、`RUN_NOT_FOUND`、`CARD_NOT_FOUND`、`FILE_NOT_FOUND`、`ASSET_NOT_FOUND` | 对应资源不存在或无权访问                                                  |
| 409       | `CONVERSATION_BUSY`、`DRAFT_VERSION_CONFLICT`、`CARD_EXPIRED`                                                                                                | 已有任务、版本冲突或回答已失效                                            |
| 409       | `RUN_NOT_RESUMABLE`                                                                                                                                          | 关联数据缺失或已确认的重连位置不合法；缓存到期本身不属于此错误            |
| 413       | `PAYLOAD_TOO_LARGE`                                                                                                                                          | HTTP 请求体在业务校验前已超过限制                                         |
| 413       | `GRAPH_TOO_LARGE`、`FILE_TOO_LARGE`                                                                                                                          | 图或文件超出相应限制                                                      |
| 422       | `GRAPH_INVALID`                                                                                                                                              | 图结构、引用关系或深度不合法                                              |
| 415       | `FILE_TYPE_UNSUPPORTED`                                                                                                                                      | 文件不在支持范围                                                          |
| 422       | `FILE_PARSE_FAILED`                                                                                                                                          | 同步处理入口的解析失败；异步处理通常通过文件 `failed` 状态反馈            |
| 409       | `FILE_LIMIT_EXCEEDED`                                                                                                                                        | 项目文件数超限，具体配置待上传任务确定                                    |
| 422       | `IDEMPOTENCY_KEY_REUSED`                                                                                                                                     | 同一操作标识被用于不同请求体                                              |
| 429       | `RATE_LIMITED`                                                                                                                                               | 超过限制，读取 `Retry-After` 后重试                                       |
| 500 / 503 | `INTERNAL_ERROR` / `SERVICE_UNAVAILABLE`                                                                                                                     | 服务内部失败或依赖不可用；对外不返回内部细节                              |
| 400       | `RESET_TOKEN_INVALID`                                                                                                                                        | 仅后续密码重置接口使用                                                    |

草稿与资产按错误原因区分状态：体积过大使用 413，结构错误使用 422。枚举和字段数值规则不在本表重复。

## 1.6 列表分页

使用 `PaginationQuery`，消息额外使用 `MessageListQuery`。客户端把上一页返回的 `nextCursor` 用于下一次查询，不自行生成游标。

```json
{ "items": [], "nextCursor": null, "hasMore": false }
```

有更多数据时给出 `nextCursor`，否则为 `null`。项目目录中嵌套列表只返回简要信息，超出部分走各资源的列表接口。排序需要稳定的并列处理；不得只按可能相同的时间戳判断位置。消息在一页内按时间正序返回，方便显示。

## 1.7 同一次操作重复请求

幂等表示网络重试或重复点击只产生一次实际效果。前端为一次操作生成 `Idempotency-Key`；重试复用原值，新的操作才换新值。

原定协议采用 UUID v4 或符合约定格式的操作标识，有效期 24 小时，按当前用户、路径和操作标识隔离。请求头的具体校验规则与存储需在实现中落入共享定义/配置。

| 情况                     | 行为                                                                              |
| ------------------------ | --------------------------------------------------------------------------------- |
| 同 key、同请求体且已完成 | 重放首次响应，包括同一个任务 ID                                                   |
| 同 key、不同请求体       | `422 IDEMPOTENCY_KEY_REUSED`                                                      |
| 同 key 首次请求仍在处理  | `409` 并返回 `Retry-After: 1`；具体错误码在实现前补齐共享常量，不借用无关业务错误 |

注册、创建项目、发消息、回答卡片、复制会话、保存资产必须携带操作标识。其他创建接口若也需防重复，应先扩展同一规则。卡片已经完成后，用新 key 重答仍应返回首次处理结果，不能再次执行。

## 1.8 请求标识与日志

客户端可发 `X-Request-Id`，服务端按 `TraceId` 格式验证，合法则沿用，否则生成新 UUID。响应头 `X-Trace-Id` 与 JSON `traceId` 一致；204 和下载至少返回响应头，事件流的 `run-start` 携带标识。

服务端在 HTTP、任务、模型和工具调用间关联这一标识。当前异常过滤器已生成错误 traceId，成功请求和完整结构化日志还需 P0-02/P0-10 实现。

## 1.9 数据表示

布尔使用 JSON 布尔值，数量和字节数使用数值，文件大小对外为 `sizeBytes`。时间按带时区字符串传输。`usage` 用于运行分析和限流，第一版不进行用户计费。

## 1.10 状态和文件能力

状态值在共享定义中维护，语义见[数据模型](./10.%20数据模型.md)。`waiting_input` 与 `interrupt` 已有 Zod 定义，但执行行为未实现。

| 文件类别 | 第一版处理要求                   | 上传后的状态                      |
| -------- | -------------------------------- | --------------------------------- |
| 文本     | 提取、分段并向量化，完成后可引用 | `processing` → `ready` / `failed` |
| 图片     | 生成文字描述并入库，完成后可引用 | `processing` → `ready` / `failed` |
| PDF/DOCX | 只保存和下载，不解析、不可引用   | `stored`                          |

## 1.11 不使用普通响应包装的情况

| 接口                | 响应方式                                       |
| ------------------- | ---------------------------------------------- |
| 流式任务接口        | SSE 事件；建立连接前的鉴权等失败仍返回普通错误 |
| 文件内容接口        | 成功返回二进制；鉴权等失败仍返回普通错误       |
| `/health`、`/ready` | 健康检查单独约定，见系统接口                   |
| 返回 204 的接口     | 无响应体，仅响应头，不能附带 JSON              |

## 1.12 安全要求

API 每次检查资源所有者，越权返回 404。CORS 精确允许前端来源、允许 Cookie，并向浏览器暴露 `X-Trace-Id` 和 `Retry-After`。Cookie 写请求还要校验来源。

上传要验证实际类型、大小并净化文件名，不能只相信浏览器的 `Content-Type`。下载经过权限检查，不暴露 MinIO 内部地址。错误和日志不泄露密钥或内部数据。

当前表结构只提供级联删除，没有软删除列或恢复接口；文档不承诺删除后可恢复。上传、删除和运行任务的失败处理见[待确认问题](../待确认问题.md)。
