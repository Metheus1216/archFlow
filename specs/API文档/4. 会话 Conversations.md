# 4. 会话、消息与草稿

> 目标接口尚未实现。字段以 `conversation.schema.ts` 为准；图定义与布局缺口见[图数据](./7.%20知识库与文件模块%20.md#76-图数据)。

## 4.1 创建会话

```http
POST /api/v1/projects/:projectId/conversations
```

请求使用 `CreateConversationInput`：

```json
{ "title": "第一版方案", "initialAssetId": "ast_1" }
```

两个字段均可省略。标题由服务端提供默认值；`initialAssetId` 必须属于当前项目，否则按资产不存在处理。指定资产时复制其业务图初始化草稿，没有指定则初始草稿为空。

返回 `201`，数据使用 `Conversation`，包含项目 ID、标题、草稿、版本、消息统计、摘要与时间，不返回消息数组。

## 4.2 获取会话详情

```http
GET /api/v1/conversations/:conversationId
```

返回 `200` 与 `Conversation`。消息另外分页查询。`draftVersion` 是客户端后续保存时使用的版本，不能自己递增后假定已保存。

当前响应中的图还使用 `LooseGraph` 读取旧模拟数据；真实图接入时需按 P0-16 统一结构，不能把宽松读取理解为任意图都可写入。

## 4.3 保存草稿

```http
PUT /api/v1/conversations/:conversationId/draft
```

请求使用 `SaveDraftInput`，全量替换业务图：

```json
{ "graph": { "nodes": [], "edges": [] }, "baseVersion": 12 }
```

服务端以版本条件更新图并增加版本，成功返回 `SaveDraftResult`：

```json
{ "draftVersion": 13, "updatedAt": "2026-11-13T16:00:00+08:00" }
```

| 错误                         | 行为                                                   |
| ---------------------------- | ------------------------------------------------------ |
| `409 DRAFT_VERSION_CONFLICT` | `data: null`；前端保留本地编辑，重新获取会话供用户处理 |
| `413 GRAPH_TOO_LARGE`        | 超过 `GraphInput` 体积限制                             |
| `422 GRAPH_INVALID`          | 结构、规模、引用、深度等不合法                         |

客户端编辑停止 3 秒后保存，不能在每次移动事件里提交。发送消息前先等保存完成。当前请求没有布局字段，尚不能保存拖拽坐标；需先解决[Q-01](../待确认问题.md#q-01-拖拽位置如何保存)，不能自动改版本后覆盖冲突。

## 4.4 获取消息列表

```http
GET /api/v1/conversations/:conversationId/messages?limit=30&direction=backward
```

请求使用 `MessageListQuery`，响应使用 `PageSchema(Message)`。不带游标时取最新一页，`backward` 加载更早消息，`forward` 加载之后消息；每页 `items` 内按时间正序，游标排除已加载边界。

消息包含文字、可空图快照和可空 `MessageMetadata`。附加数据可含一张卡片、引用列表和用量，具体定义查源码。`system` 仅后端使用，不下发给用户。

任务未结束时也返回已持久保存的部分文字；前端继续接事件，结束后按查询结果校准。查询结果和事件均按消息 ID 合并，不能生成重复消息。

## 4.5 更新会话标题

```http
PATCH /api/v1/conversations/:conversationId
```

请求使用 `UpdateConversationInput`，返回更新后的会话元信息，复用 `ConversationMeta`。具体更新时间与排序规则在 P0-15 统一；当前模拟改名不更新时间的行为不能无说明地作为正式规则。

## 4.6 删除会话

```http
DELETE /api/v1/conversations/:conversationId
```

成功返回 204 与 `X-Trace-Id`。数据库级联删除消息、任务与 Agent 状态；同时需要协调取消正在执行的任务，避免删除后仍有写入。没有恢复接口。

## 4.7 复制历史以比较另一种方案

```http
POST /api/v1/conversations/:conversationId/fork
Idempotency-Key: <本次操作标识>
```

请求使用 `ForkInput`：

```json
{ "sourceMessageId": "msg_20" }
```

返回 `201` 与 `ForkResult`，包含新会话及来源标识。复制选定消息及之前的记录，重建消息标识、卡片关联、图和条件状态，使两份会话后续修改互不影响。源消息不属于该会话返回 `404 MESSAGE_NOT_FOUND`。

最大复制范围、没有图快照时的初始化方式、暂停/卡片历史怎样复制仍需 [Q-07](../待确认问题.md#q-07-分页与复制历史的边界尚需落实)确定。当前没有正式上限，不把“超过 200 条”当作已定义的拒绝规则，也不擅自改成依赖源数据的指针式分支。

## 4.8 获取项目下的会话列表

```http
GET /api/v1/projects/:projectId/conversations?limit=20&cursor=xxx
```

用于读取超出项目目录首批范围的会话。先检查项目所有者，按更新时间与稳定的并列顺序分页，不返回消息和大图。

目标复用公共 `PaginationQuery`、`PageSchema` 和已有会话元信息；目前没有专用列表契约导出。P0-15 应先在共享包确认查询/列表项组合并同步本文，见 Q-07，不能按接口总览的路径推断完整字段已经定稿。
