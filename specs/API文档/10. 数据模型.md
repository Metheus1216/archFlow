# 10\. 数据模型

字段类型的**唯一来源**是 Zod 数据模型（`10. 数据模型（Zod）`）——TS 类型用 `z.infer` 推导。本章不再重复字段清单，只保留三类约定：**语义与错误映射**、**状态机与枚举语义**、**API ↔ 数据库字段映射**。

## 10\.1 语义约束

> 字段长度、格式、枚举取值**不在此表重复**，唯一源是 Zod（§10 的 Zod 文件）。本表只列 Zod 表达不了或需要解释的行为约束。

|对象|约束|越界响应|
|---|---|---|
|`graph` 序列化大小|`GraphInput`（常量 `GRAPH_MAX_BYTES`，按 UTF-8 字节计）|413 `GRAPH_TOO_LARGE`|
|`graph` 结构|`GraphNode` / `GraphEdge` 按 §7.6；`NodeType` 白名单；节点 ≤ 200、边 ≤ 400；`version` 可选|422 `GRAPH_INVALID`|
|`graph` 引用完整性|节点 / 边 id 唯一；边不能自环，`source` / `target` 必须存在|422 `GRAPH_INVALID`|
|资产 `graph`|不可为 `null`|422 `GRAPH_INVALID`|
|文件|单文件 ≤ 20MB（服务端配置，非 Zod）；单项目文件数上限待定|413 `FILE_TOO_LARGE` / 409 `FILE_LIMIT_EXCEEDED`|
|`email`|`Email` 先 trim + 转小写，再校验；存储、唯一性、登录比对均按归一化值|422 `VALIDATION_FAILED`|
|`id`|不透明字符串（对外 = 库内 `uuid`），客户端不得解析或拼接|—|
|时间|ISO 8601，带 `+08:00` 偏移|—|
|分页|`cursor` 不透明；`limit` 与嵌套数组条数见 `PaginationQuery` / `ProjectNode`|—|

**图错误的 HTTP 状态按原因区分，不按资源区分**：过大 → `413 GRAPH_TOO_LARGE`；结构与深度非法 → `422 GRAPH_INVALID`（草稿与资产一致）。Zod 侧由 `mapGraphError` 统一映射：带 `params.httpStatus` / `params.errorCode` 的 issue 直接采用，其余结构错误归 `422 GRAPH_INVALID`。

> 请求体在进入 Zod 前就超过 Nest body 限制时，返回的是 `413 PAYLOAD_TOO_LARGE`；进入 Zod 后才发现图超限，才是 `413 GRAPH_TOO_LARGE`。两者不要合并。

## 10\.2 状态机与枚举语义

### ConstraintCard\.status

|状态|含义|进入条件|可回退|
|---|---|---|---|
|`pending`|待回答|卡片随消息下发|是|
|`answered`|已回答|用户提交 `values`|否|
|`ignored`|用户跳过（忽略）|用户关闭 / 跳过卡片，或改为直接打字|否|
|`expired`|已失效|超时或被新卡片取代|否|

终态不可回退。重复提交返回 `200` 并重放首次的 run 结果（幂等）；超时或被新卡片取代转 `expired`。

### Run\.status

|状态|含义|备注|
|---|---|---|
|`queued`|已受理、排队中|POST 消息返回 202 时的初始态|
|`running`|生成中|SSE `status` 帧推进|
|`waiting_input`|等待人工输入|HITL 暂停，非终态；`runs.metadata.interrupt` 存当前中断|
|`succeeded`|成功|`finishReason` 通常为 `stop`|
|`failed`|失败|`finishReason = error`，错误码走 `error` 事件|
|`canceled`|用户取消|`finishReason = canceled`|

迁移为 `queued` → `running` →（HITL 时进入 `waiting_input`，恢复后回到 `running`）→ `succeeded` / `failed` / `canceled`，后三者为终态。`finishReason` 仅在终态有值，与 SSE `done` 帧保持一致。

> `waiting_input` 与 SSE `interrupt` 是 2026-11-12 新增的规划契约；实现顺序见 [`待做清单.md`](../待做清单.md) 的 P0-01。

### FinishReason

|值|含义|
|---|---|
|`stop`|模型正常结束|
|`length`|触达输出长度上限|
|`canceled`|用户取消|
|`error`|异常终止|

### File\.status

|状态|含义|
|---|---|
|`processing`|解析中，暂不可被 Agent 引用|
|`ready`|解析完成，可引用|
|`failed`|解析失败，`errorMessage` 有值，前端提示重新上传|
|`stored`|已上传但按设计不解析（pdf/docx），不可被 Agent 引用，终态|

### MessageRole

`user` / `assistant` / `system`。`system` 仅后端写入，不下发给前端渲染。

## 10\.4 实体关系与级联

`users` → `projects`（`user_id`）→ `knowledge_base` / `assets` / `conversations`（`project_id`）→ `messages`、`runs`、`agent_states`（`conversation_id`）；`documents_chunks` 挂 `knowledge_base`（`knowledge_id`）。

级联：删项目 → 级联其知识库文件、资产、会话；删会话 → 级联消息与运行记录；删文件 → 级联其切片。卡片与 `agent_states` 不单独建业务表，随消息与会话存在。
