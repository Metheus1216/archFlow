# 11\. 接入说明

### 11\.1 首屏加载



```Plain Text
1. GET /api/v1/auth/me                     → 拿用户信息（401 则跳登录）
```

### 11\.2 发消息 \+ 接流



```Plain Text
1. 生成 Idempotency-Key（每次用户操作一个）
2. POST /api/v1/conversations/:id/messages  → 202，拿 runId / streamUrl
3. fetchEventSource(streamUrl, { headers: { Authorization }, openWhenHidden: true, ... })
   ← 统一使用 @microsoft/fetch-event-source；不能用 EventSource
4. 在 onmessage 中解析 event.data（JSON），按 type 分发：
     run-start   → 记录 assistantMessageId，插入占位消息
     text-delta  → 追加到该消息 content
     graph       → 整体替换画布（最后一帧为准）
     citation    → 渲染来源角标
     constraint-card → 插入卡片（用 messageId 定位）
     title       → 更新侧边栏标题
     usage       → 可选，埋点
     done        → 收尾
     [DONE]      → 停止解析
5. 流结束后重新拉一次 GET /api/v1/conversations/:id/messages 做最终校准
```



### 11\.3 断线重连



```Plain Text
如果流异常中断（onerror / 非正常 onclose）：
  a. 先用 GET /api/v1/runs/:runId 查状态
     - succeeded / failed / canceled → 直接刷新消息列表，结束
     - 404 → 刷新消息列表，结束
     - running → 进入 b
  b. 重新建立流，带已持久化的帧 id：
     fetchEventSource(streamUrl, {
       headers: { Authorization, "Last-Event-ID": sessionStorage.getItem(`lastEventId:${runId}`) },
       openWhenHidden: true,
       onopen, onmessage, onerror,
     })
     - 200 → 从断点续传
     - 服务端缓冲已失效 → 服务端自动查库合成快照重放（前端无感）
     - 409 RUN_NOT_RESUMABLE → run 数据异常，刷新消息列表
  c. 连续失败 3 次 → 降级为 GET /api/v1/runs/:runId 轮询（约 1.5s），终态后刷新消息列表
```



**客户端实现约束（`@microsoft/fetch-event-source`）**：

- **会话内持久化帧 id**：每收到一帧，把 `event.id` 写入 `sessionStorage["lastEventId:" + runId]`。库只在当前内存会话内自动回填 `Last-Event-ID`，页面刷新后必须手动带上。
- **首次连接**：`sessionStorage` 没有值时不要发送 `Last-Event-ID: null`，应省略该请求头。
- **全量补发**：未带 `Last-Event-ID` 时服务端会从头补发，收到 `run-start` 后先清空该 assistant 气泡的本地内容再重建，避免重复追加。
- **`openWhenHidden: true`**：默认值 `false` 会让标签页隐藏时主动 abort 连接、可见后再重连；生成长任务不应因此中断。
- **默认无限重试**：库的 `onerror` 不抛错就会一直重试。必须在 `onopen` 里检查 `response.ok`，并在 `onerror` 中区分可重试与不可重试：
  - `401` → 先静默刷新 token，再抛出可重试错误让库重连。库在创建时**拷贝**了 `headers`，外部改原对象不会生效；应通过 `fetch` 选项在每次请求时注入最新 `Authorization`（`{ ...init.headers, Authorization }`，注意别覆盖库自动维护的 `last-event-id`）。
  - `404` / `409` → 抛出不可重试错误，`onerror` 中继续 `throw` 终止重试，转刷新消息列表。
  - `5xx` / 网络错误 → 指数退避 `1s → 2s → 4s`，最多 3 次；超过后终止并降级为轮询 `GET /runs/:runId`。
- **结束语义**：收到 `[DONE]` 后主动 `abort()`（或等服务端关闭），避免库把正常结束当成断线继续重连。
- **`text-delta` 的 `replace`**：缓冲失效重放时，服务端会发 `replace: true` 的全量文本帧，前端应整体替换当前气泡内容，而不是追加。



### 11\.4 卡片交互



```Plain Text
1. 从 message.metadata.card 渲染（status === "pending" 才可点）
2. 用户选择 → POST /api/v1/conversations/:id/messages/:messageId/answer
3. 202 拿新 runId → 走 11.2 的接流逻辑
4. 本地先把卡片置灰（乐观更新），流结束后以重新拉取的数据为准
```



> **刷新后卡片不丢**：因为卡片持久化在 `metadata.card`，`GET /messages` 会带回来。

### 11\.5 文件上传与解析等待



```Plain Text
1. POST /api/v1/projects/:id/files (multipart)
2. text / image：status 为 "processing" → UI 显示「解析中」；pdf / docx：直接 "stored"，无需等待
3. 仅对 text / image 轮询 GET /api/v1/projects/:id/files/status?ids=...（2s 起，指数退避，最长 60s）
4. status 变 "ready" → 可被 AI 引用；变 "failed" → 展示 errorMessage；"stored" → 仅展示文件，不可引用
```

```Plain Text
用户点击某个资产 → GET /api/v1/projects/:id/assets/:assetId?includeGraph=true  拿完整 graph
```



### 11\.7 401 统一处理



```Plain Text
拦截器收到 401：
  code === "TOKEN_EXPIRED" → 静默刷新（并发去重）→ 重放原请求一次
  code === "TOKEN_MISSING" / "TOKEN_INVALID" / "REFRESH_INVALID"     → 清本地态 → 跳登录
```
