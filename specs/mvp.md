# 第一版需求边界（MVP）

> 本文定义第一版必须达到的产品行为，不表示这些功能已经实现。当前进度见[待做清单](./待做清单.md)，项目全貌见[项目说明](./项目说明.md)。MVP 指能够完整使用的第一版范围。

## 1. 核心目标

让用户完成“描述项目需求 → 助手追问关键条件 → 生成架构说明和图 → 用户调整 → 保存为命名方案”的完整过程。优先保证桌面浏览器体验与数据保存的可靠性。

## 2. 必须具备的能力

### 用户账号

支持邮箱密码注册、登录、退出和查询当前用户。短期访问凭证过期时，用浏览器安全 Cookie 中的刷新凭证续期；刷新失败后回到登录页。每位用户只能访问自己的项目。

### 项目与会话

用户可以创建和删除项目，在项目下创建、重命名、切换和删除会话。没有项目时显示创建引导；有项目时显示项目目录与历史会话，标明当前会话。

### 对话与条件收集

助手逐段显示回复，并通过文字或单选、多选、输入卡片收集团队、预算、访问量等条件。需要用户回答时暂停执行；回答保存后继续同一任务。界面显示“查询项目资料”“生成架构图”等执行状态。

确认的条件和执行状态必须保存到数据库。用户刷新或网络重连后应能恢复已有内容；重复请求不能重复创建任务或重复执行写入操作。

### 图的查看、调整与草稿保存

使用 React Flow 展示节点与连接，支持拖拽、缩放和 Dagre 自动布局。编辑停止一段时间后自动保存，保存时比较版本号；发现其他窗口已经修改则提示冲突，不直接覆盖。

刷新后应恢复已经保存的图和用户布局。**现有图定义只保存节点与连接，不包含位置；布局如何保存尚待补齐**，见[Q-01](./待确认问题.md#q-01-拖拽位置如何保存)。这项缺口解决前，不能宣称画布保存已满足验收。

### 上传资料与有依据的回答

支持上传文本、图片、PDF 和 DOCX。文本与图片属于第一版处理范围：文本提取后分段，图片先生成文字描述，再供本项目检索和回答使用。PDF/DOCX 只保存原文件，不解析、不可引用。

只有处理完成的文件才能作为回答依据。引用显示来源；检索必须限定当前项目，不能混用其他项目的资料。文件可以查看状态、鉴权下载和删除。

### 保存方案与历史恢复

用户可以把当前图保存为命名的“架构资产”，之后查询、更新、删除或作为新会话的起点。当前资产范围是图和基本信息，不包含完整技术报告导出。

历史消息可以关联当时的图快照，供用户恢复。也可以复制某条消息及之前的记录，新建独立会话比较另一种方案。复制后的消息和状态不能继续依赖原会话。

## 3. 第一版不包含的能力

| 能力                   | 边界                                                  |
| ---------------------- | ----------------------------------------------------- |
| PDF/DOCX 内容解析      | 只上传与保存；后续单独评估 Go 解析服务                |
| 异步消息队列           | 不使用 BullMQ 或 RabbitMQ；生成在 Node.js 进程内执行  |
| 多人同时编辑           | 不实现 WebSocket/Yjs 画布同步；版本冲突检测仍然必须有 |
| 多人项目权限           | 每个项目只有一个所有者，不建立项目成员体系            |
| 通用 Agent 框架        | 不引入 LangChain、LangGraph 或 Vercel AI SDK          |
| 外部工具协议与技能产品 | 不实现 MCP、产品级 Skill 或多 Agent 编排              |
| 用户自带模型密钥       | 不提供 BYOK、自定义服务地址；平台模型选择另作后续规划 |
| 密码重置、GitHub 登录  | 密码重置只保留设计；GitHub 按钮不代表已纳入第一版     |
| 移动端完整适配         | 先完成桌面工作台                                      |

## 4. 验收场景

以下七项需要使用真实 API、真实数据库和实际模型完成。模拟数据与静态界面不能作为通过证据，当前均未完成整体验收。

| 编号 | 用户操作与预期结果                                                                    |
| ---- | ------------------------------------------------------------------------------------- |
| AC1  | 新用户注册登录，看到无项目引导，创建首个项目和会话；刷新后仍能访问，其他用户无法读取  |
| AC2  | 发送项目需求后收到逐段回复和条件卡片；重复发送同一次请求不会产生重复任务              |
| AC3  | 回答卡片后继续原任务并得到合法架构图；等待、失败、取消和网络重连都有明确反馈          |
| AC4  | 调整节点位置后自动保存；刷新恢复图和布局；两个窗口同时保存时返回冲突且不覆盖数据      |
| AC5  | 保存命名架构资产后在列表中出现，能够重新加载和更新                                    |
| AC6  | 恢复历史图；从历史消息复制新会话后，两份会话的后续修改互不影响                        |
| AC7  | 上传文本与图片后，助手能基于本项目内容回答并给出来源；PDF/DOCX 显示仅存储，不能被引用 |

每项通过时，在[待做清单](./待做清单.md)补充对应测试、操作步骤和证据链接。具体协议见[数据流](./数据流.md)和[API 文档](./API文档/README.md)。
