# 9. 进程与依赖检查

> 当前接口尚未实现，由 P0-02 完成。两条路径不带 `/api/v1`，NestJS 注册全局业务前缀时需排除它们。

## 9.1 进程检查

```http
GET /health
```

仅检查 API 进程能否响应，不访问数据库等依赖。成功返回 200 与共享 `HealthResult`：

```json
{ "status": "ok" }
```

成功响应不使用普通业务包装。它不能证明登录、模型或文件处理可用。

## 9.2 依赖就绪检查

```http
GET /ready
```

检查 PostgreSQL、Redis 和 MinIO，并为检查设置超时。依赖全部就绪返回 200 和 `HealthResult`，不可用返回 503。失败响应的具体精简结构尚无共享定义，P0-02 需先补 Zod 与接口测试，不对外泄露连接地址或凭证。

第一版没有消息队列，因此不检查 RabbitMQ/BullMQ。API 启动成功也不等于就绪，因为当前 Redis/MinIO 连接失败不一定阻止监听端口。
