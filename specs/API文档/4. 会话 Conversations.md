```HTTP
GET /api/v1/conversations/:conversationId
```



返回会话信息和当前画布草稿。完整消息通过 4\.4 分页读取。



**响应 ****`200 OK`**：



```JSON

  "projectId": "prj_1",
  "title": "订单服务拆分",
  "draftGraph": { "nodes": [{ "id": "orders", "type": "service", "label": "订单服务" }], "edges": [] },
  "draftLayout": [{ "nodeId": "orders", "x": 160, "y": 80 }],
  "draftVersion": 12,

  "lastMessage": {
    "id": "msg_48",
    "role": "assistant",
    "contentPreview": "建议按领域拆成三个服务……",
    "createdAt": "2026-11-08T16:40:00+08:00"

  "updatedAt": "2026-11-08T16:40:00+08:00"
```

|字段|说明|
|---|---|
|`draftLayout`|已保存的节点位置，按 `nodeId` 对应 `draftGraph`。字段缺省或节点没有保存位置时，用自动布局计算。|
|`draftVersion`|草稿版本号，用于 4\.3 的乐观锁|



## 4\.3 保存草稿图



```HTTP
PUT /api/v1/conversations/:conversationId/draft
```



一次保存替换整张草稿及其布局。持久化前会检查会话归属和草稿版本。

本地工作台使用 `/api/mock/conversations/:conversationId/draft`，与会话详情共用文件存储。生产接口接入进度见 [P0-16](../待做清单.md#2-p0mvp-主链路)。



**请求体**：



```JSON
{
  "graph": { "nodes": [{ "id": "orders", "type": "service", "label": "订单服务" }], "edges": [] },
  "layout": [{ "nodeId": "orders", "x": 200, "y": 96 }],
  "baseVersion": 12
}
```



|字段|必填|说明|
|---|---|---|
|`graph`|是|完整架构图。校验规则见 `GraphInput`。|
|`layout`|否|节点在画布坐标系中的位置。每个 `nodeId` 只能出现一次，且必须属于本次提交的图。省略此字段会清除原布局。|
|`baseVersion`|是|开始编辑时读取的 `draftVersion`。同一页面连续保存成功时，后续未提交的调整沿用刚返回的版本。|



**响应 ****`200 OK`**：



```JSON
{ "draftVersion": 13, "updatedAt": "2026-11-08T16:51:00+08:00" }
```



**错误**：



|HTTP|code|说明|
|---|---|---|
|404|`CONVERSATION_NOT_FOUND`|会话不存在或不属于当前账号。|
|409|`DRAFT_VERSION_CONFLICT`|草稿已有更新，`data` 为 `null`。使用会话详情接口读取最新草稿。|
|413|`GRAPH_TOO_LARGE`|图序列化超过 `GRAPH_MAX_BYTES`|
|422|`GRAPH_INVALID`|图的结构或节点位置不合法。|



同一草稿的版本检查和写入在同一次操作完成，保存成功后版本递增。工作台在最后一次操作结束 3 秒后保存，同一页面的请求按顺序提交。生产接口的限流策略随正式接入确定。

## 4\.7 基于历史消息分叉

本地工作台使用 `POST /api/mock/conversations/:conversationId/fork`。正式接口接入进度见 [P0-18](../待做清单.md#2-p0mvp-主链路)。恢复快照使用 [保存草稿接口](#43-保存草稿图)，确认后提交历史消息保存的图和当前草稿版本。


```HTTP
POST /api/v1/conversations/:conversationId/fork
Idempotency-Key: <uuid>
```



**请求体**：



```JSON
{ "sourceMessageId": "msg_20" }
```



**响应 ****`201 Created`**：



```JSON
{
  "id": "cnv_2",
  "projectId": "prj_1",
  "title": "订单服务拆分（分叉）",
  "draftGraph": { "nodes": [], "edges": [] },
  "draftVersion": 0,
  "messageCount": 21,
  "lastMessage": {
    "id": "msg_fork_21",
    "role": "user",
    "contentPreview": "那消息队列怎么选？",
    "createdAt": "2026-11-08T17:00:00+08:00"
  },
  "createdAt": "2026-11-08T17:00:00+08:00",
  "updatedAt": "2026-11-08T17:00:00+08:00",
  "forkedFrom": { "conversationId": "cnv_1", "sourceMessageId": "msg_20" }
}
```



**语义约定**：



- 按原顺序复制 `sourceMessageId` 及其之前的消息，包括各条消息保存的 `graphSnapshot`。复制后的消息与卡片在新会话中拥有各自的 ID。

- 用截至所选消息时保存的架构图初始化新会话的草稿，无可用图时从空画布开始。旧记录缺少当时的画布信息时，使用所选消息及之前最近一次保存的图。历史快照没有节点位置，首次打开会自动布局。

- 两个会话分别保存草稿和后续消息。源会话的待回答卡片在新会话中作为过期历史显示。

- `sourceMessageId` 不属于该会话 → `404` / `MESSAGE_NOT_FOUND`。

- 同一源会话、同一消息使用同一个 `Idempotency-Key` 重试时，返回首次创建的结果。同一个键指向该会话的另一条消息时，返回 `422 IDEMPOTENCY_KEY_REUSED`。

    

> 超过 `FORK_MESSAGE_LIMIT` 时返回 `422 VALIDATION_FAILED`。上限按实际复制的消息数计算，可以换一条更早的消息。
