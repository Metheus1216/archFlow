# 术语说明

本文解释本项目中确有用途的技术词。正文优先说明行为，代码字段、协议名称和库名保留原名，便于查实现。

| 词语                        | 在 ArchFlow 中的含义                                  | 具体例子或边界                                                      |
| --------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------- |
| MVP                         | 第一版必须能完整使用的最小范围                        | 完成从输入需求到保存方案的过程，范围见 `mvp.md`                     |
| 约束                        | 会影响技术选择的条件                                  | 团队人数、预算、预计访问量、交付时间、数据安全要求                  |
| Agent                       | 按明确步骤调用模型和工具、处理结果并保存状态的程序    | 提取条件 → 需要时追问 → 查资料 → 生成图；不是另一个独立服务         |
| 契约 / Schema               | 交换数据时必须遵守的字段与校验规则                    | `SaveDraftInput` 规定保存草稿要带图和版本号                         |
| Zod                         | 在运行时检查数据并推导 TypeScript 类型的库            | 检查图中连线的终点是否存在；不保证方案本身合理                      |
| 模拟数据 / Mock             | 用来开发界面、暂时代替真实后端的数据                  | 当前 `/api/mock` 把项目和消息保存在本机 JSON 文件中                 |
| run                         | 一次生成任务及其运行记录                              | 一条消息触发任务；任务等待回答时可暂停，回答后继续同一任务          |
| 状态机 / Workflow           | 限定程序可以处于哪些步骤，以及何时转到下一步          | 等待回答时不应继续生成；取消后不再进入成功状态                      |
| 工具调用 / Function Calling | 模型请求程序执行一个已定义操作                        | 模型给出检索参数，由服务端实际查项目资料，并校验输入输出            |
| ReAct                       | 模型根据工具结果决定下一步动作的循环方式              | 本项目只允许在指定步骤中有限次调用，避免无限循环                    |
| 人工介入 / HITL             | 程序暂停，等待用户回答或确认后再继续                  | 信息不够时提出卡片问题；并不表示用户在看模型的内部思考              |
| interrupt / resume          | 暂停记录 / 根据该记录继续执行                         | 暂停保存到数据库，恢复时不重复执行已完成的写入操作                  |
| SSE                         | 服务端通过一个 HTTP 连接持续向浏览器发送事件          | 分段显示回复、更新图、通知任务暂停；浏览器使用 `fetch-event-source` |
| 事件重放                    | 重连时补发先前发送过的数据                            | 用 `Last-Event-ID` 标记已经收到的位置，避免重复追加文字             |
| 幂等                        | 同一次操作重复请求，只产生一次实际效果                | 网络重试时复用 `Idempotency-Key`，避免创建两次任务                  |
| 防抖                        | 一段时间没有新操作后，才执行保存                      | 拖拽结束并停顿后保存，不在每个鼠标移动事件里写数据库                |
| 乐观锁                      | 保存时比较客户端版本和数据库版本                      | 两个窗口从同一版本开始修改，后保存的窗口收到冲突提示                |
| 架构资产                    | 用户明确保存的一份命名架构图                          | “低成本部署方案”；当前只保存图及基本信息，不等同于完整设计报告      |
| 快照                        | 某条消息对应时刻的图副本                              | 恢复当时的结构；布局能否一并恢复取决于布局保存契约                  |
| 分支 / Fork                 | 复制选定位置及以前的消息，创建独立会话                | 从同一讨论位置尝试另一种技术方案，之后两份会话分别修改              |
| 检索增强回答 / RAG          | 先查本项目资料，再把相关片段交给模型组织回答          | 回答时带资料引用；找不到依据时不能编造来源                          |
| 向量 / Embedding            | 把文本转换成可比较相似度的数字序列                    | 用同一模型和维度处理文档与查询；它不是文本摘要                      |
| pgvector / HNSW             | PostgreSQL 的向量能力 / 用于加速相似度检索的索引      | 每次查询还必须限定 `project_id`，防止混入其他项目资料               |
| topK / rerank               | 先取若干检索候选 / 再给候选重新排序                   | 第一版只做向量检索；重新排序要在评测证明有效后再做                  |
| caption                     | 视觉模型对图片内容生成的文字描述                      | 图片描述可以进一步切片和检索，不能把图片标为 `ready` 就假设内容正确 |
| Prompt                      | 发送给模型的指令、背景和当前问题                      | 项目条件、资料片段与用户消息按顺序组织，上传内容当作资料处理        |
| token                       | 模型计量输入和输出长度的单位                          | 用于记录调用量、控制上下文和成本；本项目第一版不做用户计费          |
| traceId                     | 用于把一次请求的响应和服务端日志联系起来的标识        | 用户报错时提供该值；目前真实 API 主要在异常路径中生成               |
| 结构化日志 / 运行观测       | 用固定字段记录请求、耗时和失败原因                    | 便于统计生成成功率与排查断线；相关完整能力尚未实现                  |
| golden cases                | 预先选定、可以反复运行的测试问题和判断标准            | 比较修改提示词或模型前后，关键条件是否仍被正确保留                  |
| groundedness                | 回答的结论是否得到所引用资料的支持                    | 引用了一份文件，不等于文件支持回答中的每一句话                      |
| Provider / Adapter          | 模型供应商 / 把不同供应商接口转换为内部调用方式的代码 | 对话、图片理解、向量化可以使用不同模型                              |
| MCP                         | 接入外部工具的一种协议                                | 后续可接外部系统；当前产品没有相关客户端或服务端                    |
| Skill                       | 可复用的任务指令与工具配置                            | 产品功能尚未实现；与仓库中的开发辅助技能不是同一件事                |
| BYOK                        | 用户提供自己的模型服务密钥                            | 当前未立项；平台预设模型选择不包含这一能力                          |
| RabbitMQ / 死信队列（DLQ）  | 后续文档处理的消息队列 / 保存反复处理失败任务的队列   | 第一版不引入；以后与 Go 文档解析服务配套评估                        |
| Outbox                      | 在数据库中记下待发送消息，再可靠发送的方式            | 解决“业务数据保存成功，但队列消息没发出去”的问题；属于后续设计      |
| 模块化单体                  | 按业务模块分代码，但先部署为一个后端应用              | 第一版 Agent 与 API 同进程，便于实现和排查                          |
| Monorepo                    | 用一个代码仓库管理多个应用和共享包                    | `apps/web`、`apps/api` 与 `packages/*` 用 pnpm workspace 关联       |

看到“闭环”“收口”“接线”“地基”等泛化说法时，应写出实际动作，例如“接入真实登录接口”“移除模拟请求”“完成上传后可引用的验收”，避免用这些词代替完成条件。
