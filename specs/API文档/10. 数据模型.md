# 10. 数据含义与存储映射

字段的唯一维护位置是[共享源码](../../packages/shared/src/schemas/)，入口见[Zod 索引](./10.%20数据模型（Zod）.md)。本章解释字段含义、状态变化和数据库映射，不保存另一份接口类型。

## 10.1 语义与校验

| 对象     | 规则                                                     | 失败处理                                                           |
| -------- | -------------------------------------------------------- | ------------------------------------------------------------------ |
| 图       | 按 `GraphInput` 检查字段、规模、深度、重复标识和连线引用 | 体积过大为 `413 GRAPH_TOO_LARGE`，其他图错误为 `422 GRAPH_INVALID` |
| 资产     | 图不能为空，使用业务图而非组件内部对象                   | `422 GRAPH_INVALID`                                                |
| 文件     | 服务端校验允许类型、内容真实性和配置大小                 | 分别为文件类型/体积错误；处理失败写文件状态                        |
| 邮箱     | 按 `Email` 去空白、转小写、校验；登录和去重使用同一值    | `422 VALIDATION_FAILED`                                            |
| 外部标识 | 来自数据库 UUID，客户端按字符串使用                      | 资源不存在或越权返回对应 404                                       |
| 时间     | 带时区的 ISO 8601；Zod 允许合法偏移                      | 不把不同合法时区误判为非法                                         |
| 分页     | 输入和嵌套数量由共享定义控制，游标不透明                 | 不自行解析或生成游标                                               |

请求体在进入业务 Zod 前就超过 HTTP 限制时为 `413 PAYLOAD_TOO_LARGE`，与图自身过大不同。错误响应 `data` 始终为 `null`。

`Graph` 约束字段与规模，`GraphInput` 还检查引用完整性；不能只用 `Graph.parse` 就声称重复 ID、悬空边等已验证。图输入拒绝自身连接，未实现对所有多节点环路的检查，不能描述为“所有环都禁止”。

当前会话/消息使用 `LooseGraph` 兼容模拟数据，用户布局也尚无持久化契约。图生成、草稿、资产与快照统一使用业务结构是目标，仍需 P0-16 完成迁移。

## 10.2 状态语义

### 条件卡片

卡片初始为待回答，之后可变为已回答、忽略或失效。后三者不能退回待答。重复提交已回答卡片重放首次结果，不重复执行。超时、用户转为文字回答或新卡片替代时如何处理，需要与暂停状态一并定义。

### 生成任务

| 状态            | 含义                       | 是否结束 |
| --------------- | -------------------------- | -------- |
| `queued`        | 请求已受理，尚未执行       | 否       |
| `running`       | 正在执行模型和工具步骤     | 否       |
| `waiting_input` | 已保存暂停点，等待用户     | 否       |
| `succeeded`     | 已保存成功结果             | 是       |
| `failed`        | 已保存失败和可用的部分结果 | 是       |
| `canceled`      | 主动取消或等待超时         | 是       |

正常流转为受理 → 运行 → 成功/失败/取消；运行中可以进入等待输入，恢复后回到运行。终态不再继续。`finishReason` 仅终态有值，与 `done` 对齐。

`stop` 表示正常完成，`length` 表示达到输出长度限制，`canceled` 表示取消，`error` 表示异常。达到长度上限是否仍足以作为可用结果，需要执行层校验后判断，不能一律视为完整成功。

现有 Zod 接受上述状态字段，但还没有完整表达所有状态组合的约束；执行层和接口测试需要保证时间、错误与结束原因一致。进程重启后的残留运行态见 Q-03。

### 文件

`processing` 处理中，不可引用；`ready` 处理和检索入库完成，可引用；`failed` 处理失败并携带错误；`stored` 仅保存原文件，不可引用。PDF/DOCX 使用 `stored`。不能把“MinIO 写入成功”直接当成文本或图片已经可检索。

### 消息与执行阶段

`system` 消息仅后端使用，消息列表只下发用户和助手消息。`RunStage` 是界面展示的当前阶段，不是持久化 Agent 步骤定义，也不是任务终态。

## 10.3 API 与数据库映射

| API 字段                                        | 数据库来源                                         | 说明                                               |
| ----------------------------------------------- | -------------------------------------------------- | -------------------------------------------------- |
| `id`                                            | `uuid`                                             | 内部 `id BIGINT` 不返回                            |
| `projectId`、`conversationId`、消息 ID          | 对应内部外键指向行的 `uuid`                        | 不能直接把 BIGINT 改名返回                         |
| 项目 `name`                                     | `project_name`                                     | 显式转换字段名                                     |
| `draftGraph` / `draftVersion`                   | `current_draft_graph` / `draft_version`            | 当前图与保存版本                                   |
| `graphSnapshot`                                 | `messages.graph_snapshot`                          | 某条消息关联的图                                   |
| 资产 `graph`                                    | `assets.graph_data`                                | 列表省略，详情按需要返回                           |
| `fileName`、`fileType`、`mimeType`、`sizeBytes` | `file_name`、`file_type`、`mime_type`、`file_size` | 内部 `file_url` 不返回                             |
| `metadata`                                      | `messages.metadata`                                | 使用 `MessageMetadata`，包含卡片、引用与用量       |
| 卡片 `answeredAt`                               | `metadata.card.answeredAt`                         | 不单独建卡片表                                     |
| `finishReason` / `finishedAt`                   | `finish_reason` / `finished_at`                    | 任务结束信息                                       |
| `error`                                         | `error_code` / `error_message`                     | 仅对外展示安全错误信息                             |
| 用量                                            | `runs.usage`、`messages.metadata.usage`            | 依相应查询/事件契约返回，当前 `Run` 不直接包含用量 |
| `lastActiveConversationId`                      | 根据会话更新时间查询得到                           | 数据库没有同名列                                   |
| `messageCount`、`lastMessage`                   | 消息查询结果                                       | 非独立存储列                                       |

服务端需显式序列化并校验响应，不能直接返回 ORM 实体。`runs.metadata` 中的暂停信息供内部恢复使用，不直接暴露整列。

## 10.4 表关系与删除

用户拥有项目；项目包含文件、资产和会话；会话包含消息、任务和一行 Agent 状态；文件关联检索片段。卡片嵌在消息中，`agent_states` 则确实是独立数据库表。

当前外键按关系级联物理删除，没有软删除或回收站。MinIO 文件需要另外清理，正在执行的任务也需要协调停止。具体列和索引见[表设计](../表设计.md)。
