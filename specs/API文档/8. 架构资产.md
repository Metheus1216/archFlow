# 8. 命名架构方案（架构资产）

架构资产是用户明确保存的一份命名图及基本信息，不是完整设计报告或代码生成包。当前真实接口尚未实现，字段位于 `asset.schema.ts`。

## 8.1 保存新方案

```http
POST /api/v1/projects/:projectId/assets
Idempotency-Key: <本次操作标识>
```

请求使用 `AssetInput`：

```json
{ "name": "低成本部署方案", "graph": { "nodes": [], "edges": [] } }
```

名称可在项目内重复。图必须通过 `GraphInput`，不能为 `null`。成功返回 `201` 与 `AssetMeta`，不重复返回已经提交的图。

图过大为 `413 GRAPH_TOO_LARGE`，结构或引用不合法为 `422 GRAPH_INVALID`。布局如何随方案保存需先解决 Q-01，不能把自动重排称为恢复原布局。

## 8.2 查询方案列表

```http
GET /api/v1/projects/:projectId/assets?limit=20&cursor=xxx
```

使用 `AssetListQuery`，返回 `PageSchema(AssetMeta)`，不含图。与项目目录使用的更精简 `AssetBrief` 区分，不能假定两者字段完全相同。

## 8.3 查询详情

```http
GET /api/v1/projects/:projectId/assets/:assetId?includeGraph=true
```

使用 `AssetDetailQuery`。按共享默认值包含图时返回 `Asset`；明确 `includeGraph=false` 时返回 `AssetMeta`。点击资产时再加载图，避免列表重复传输完整数据。

任何查询都验证资产属于当前项目且项目属于当前用户，否则 404。

## 8.4 更新已保存方案

```http
PATCH /api/v1/projects/:projectId/assets/:assetId
```

请求使用 `AssetUpdateInput`，名称和图至少提供一项。成功返回更新后的 `Asset`。图校验规则同保存；空更新返回 `422 VALIDATION_FAILED`。

当前设计没有资产版本字段，多窗口同时更新资产的覆盖策略与草稿不同，不能声称也具备 `baseVersion` 保护；后续有需要时另扩展契约。

## 8.5 删除方案

```http
DELETE /api/v1/projects/:projectId/assets/:assetId
```

成功返回 204 与 `X-Trace-Id`，没有恢复接口。已经复制到独立会话的图不应依赖此资产继续存在，创建会话时应保存副本。
