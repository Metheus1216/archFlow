## 0. 当前状态

- 前端：登录/工作台界面，7 个模拟路由文件、11 个 HTTP handler。项目、会话和用户消息保存在本机 JSON；没有真实登录或模型回复。
- API：NestJS 启动、数据库/Redis/MinIO 客户端、全局校验和异常过滤器。业务 Controller 为 0，健康检查未实现。
- Agent：引擎、状态、模型、提示词和工具仍是占位文件。
- 数据库：9 表实体、初始迁移、运行元数据与状态版本增量迁移。初始迁移有历史真实执行记录；增量迁移未有真实库复核证据。
- 共享定义：运行状态、暂停事件和业务图已有 Zod；旧模拟图读取兼容、布局、恢复输入等仍需处理。
- 验证：本次 `pnpm test` 为 9/9；默认并行 `pnpm typecheck` 内存失败，串行同范围检查通过，详见[审计记录](./问题记录/2026-11-13-项目文档审计与整理.md)。7 项第一版场景均尚未完成真实整体验收，不能把模拟演示计为通过。

API 规划共 38 个方法/路径，其中第一版 36 个，暂缓的密码重置 2 个；这不是已实现接口数量。

认证和会话先于生成，因为生成任务需要真实用户与消息；图定义和保存先于模型图生成，避免前后端各自定义一套图。权限、错误路径、测试与实际日志随每一步完成。

下一批具体工作建议：先实现系统检查与接口测试入口，同时复核增量迁移；随后完成认证。布局和暂停设计在相关任务开始前定稿，不把未确定字段直接写成接口事实。
