# 11. 前端调用顺序

> 以下是接入真实后端的目标流程，当前前端仍读取模拟数据，SSE 客户端尚未实现。本文负责调用顺序，字段规则看共享定义，执行细节见[Agent 接口](./5.%20Agent.md)。

## 11.1 页面加载和创建项目

1. 页面重载后先调用刷新接口恢复内存访问凭证，再查询当前用户；失败则回登录页。
2. 获取项目目录，空列表显示创建引导。用户指定会话时优先加载；否则使用 `lastActiveConversationId`，没有会话则提供创建入口。
3. 分别获取会话详情和分页消息，不在项目目录响应里传整段聊天或图。
4. 创建项目后另建首个会话；第二步失败只重试建会话，避免重复项目。

接入时同时替换浏览器 hooks 和 Next.js 服务端页面读取。当前工作台的 `page.tsx`、`layout.tsx` 直接读取 `mock-db`；首页创建项目通过 hooks 调模拟接口。不能只修改 API 基础地址。

## 11.2 发送消息和接收事件

1. 先完成待保存草稿，处理可能的版本冲突。
2. 为此次操作生成 `Idempotency-Key`，提交消息，保存返回的任务及消息 ID。
3. 使用服务端返回的 `streamUrl` 连接，按 API 来源解析地址，避免业务前缀重复拼接；每次请求携带最新访问凭证。
4. 首次/全量 `run-start` 建立消息关联；`resume: true` 保留已有内容。增量重连可以直接收到下一帧。
5. 文字按 `replace` 决定追加还是覆盖；图整体替换；卡片、引用、标题与状态更新各自界面。
6. 收到 `interrupt` 时保存等待状态并停止重试；收到终态后读取最终消息，按 ID 更新，正常结束不再重连。

未收到明确结束/暂停而连接关闭时才进入重连处理。切换会话或主动取消接收时，也要终止客户端旧连接，避免把后续事件写进新会话。

## 11.3 重连和定期查询

每个任务保存最后已应用的帧 ID。页面内可用 `sessionStorage` 恢复位置；只保存已经正确解析并应用的帧，首次没有值则省略请求头，不能发送字符串 `null`。

| 查询结果         | 动作                                              |
| ---------------- | ------------------------------------------------- |
| 受理或运行中     | 按已知帧 ID 重连；缓存失效时接受服务端全量覆盖    |
| 等待输入         | 先恢复消息，再连接恢复暂停界面；不要持续重连/轮询 |
| 成功、失败、取消 | 拉最终消息并结束                                  |
| 404 或不可恢复   | 停止连接，刷新会话数据并显示原因                  |

网络错误/5xx 可以按 1、2、4 秒退避，连续 3 次仍失败则改为定期查询状态。401 按统一认证策略刷新一次，再重新连接；404/409 不盲目重试。

`fetch-event-source` 默认重试行为需要主动约束。用 `openWhenHidden: true` 避免切换标签页自动中断；通过每次 fetch 注入最新认证头，保留库维护的 `Last-Event-ID`，不要假设修改最初的 headers 对象会自动生效。

全量恢复按消息 ID 替换对应文字，不能重复追加，也不能把历史任务恢复出来的图覆盖到另一个已切换的会话。API 重启后的任务状态尚需 Q-03 确定。

## 11.4 卡片回答

根据 `metadata.card` 与有效期决定是否可答，提交后锁定重复点击。成功接续原任务并连接返回地址；重复提交返回首次结果，不再插入第二份助手消息。失败恢复可操作状态并提示。

等待任务恢复时，使用 `resume: true` 保留已有文字，不能照旧文档一律“拿新 runId”。普通文本如何回答当前暂停卡片见 Q-02，落实共享定义后再开发。

## 11.5 编辑与保存

本地记录未保存改动及当前版本，停止操作 3 秒后提交。成功更新版本；冲突保留本地改动并重新获取会话供处理，不能自动以新版本覆盖。

发送消息前、切换会话和离开页面时要协调未保存编辑。布局字段尚未定义，不能把当前只含节点/连接的保存请求算作布局持久化。

## 11.6 文件与命名方案

上传原文件后，只对处理中状态查询批量状态接口；逐步延长间隔，最大间隔 60 秒。可用/失败/仅存储状态停止轮询，切换页面时释放定时任务。文本和图片按第一版要求处理，PDF/DOCX 不进入引用。

命名方案列表先取基本信息；点击时加载含图详情。切换到资产图前处理当前未保存编辑，不能无提示丢弃。

## 11.7 错误与认证

普通错误使用 `code` 与可选 `errors` 展示，`data` 为 `null`。版本和活跃任务信息不能从错误体里取。下载成功与事件流成功不是 JSON 包装，失败时仍按 HTTP 状态和错误包装处理。

对访问凭证过期统一去重刷新；注册/登录错误不能触发刷新。跨来源请求刷新 Cookie 时需要携带凭证，且后端允许对应来源。刷新失败清理内存凭证和提示 Cookie，并停止旧任务连接。
