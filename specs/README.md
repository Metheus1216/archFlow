# 项目文档导航

第一次了解 ArchFlow，先读[项目说明](./项目说明.md)。它回答项目解决什么问题、目前有哪些实际成果、接下来按什么顺序开发。

## 如何判断一段内容的性质

- **当前实现**：能在仓库找到对应代码；是否运行验证通过，需要另外看验证记录。
- **第一版要求**：产品需要具备的目标行为，不能据此认定已经完成。
- **后续扩展**：第一版完成以后再评估，不属于当前开发范围。
- **待确认**：现有资料不足或相互冲突，相关实现应先补齐共享数据定义。

请求与响应的字段、格式、长度和枚举以 [`packages/shared/src/schemas/`](../packages/shared/src/schemas/) 为准；数据库结构以[实体](../packages/db/src/entities/)和[迁移](../packages/db/src/migrations/)为准。文档负责解释含义与流程，不再手抄整份 Zod 代码。

## 维护方式

开发进度只在[待做清单](./待做清单.md)更新。项目说明中的现状是注明日期的核查结果；发生阶段性变化时再复查。实施过程和命令结果放在 `问题记录/`，历史代码副本放在 `archive/` 并标明失效日期。

本项目目前没有 `cc_docs/`。继续使用现有 `specs/` 承接需求、任务、决策和验证记录，避免建立两套目录维护同一批内容。根目录 `AGENTS.md` 保留项目规则与入口，不存放阶段进度。
