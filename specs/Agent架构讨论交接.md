# ArchFlow 项目接手说明

ArchFlow 是一个个人架构图工作台。你在聊天框里描述系统，AI 助手会在信息不足时追问，然后生成架构图。你可以在右侧画布调整它，满意后保存到项目，也可以从历史记录继续。项目仅供所有者使用，不做多人实时编辑或项目成员管理。前 3 节描述预期体验，第 4 节记录当前进度。 [需求与验收](mvp.md)

## 1. 从一句话到保存架构图

1. 你输入「画个架构图」，助手问「要给什么系统画图？」你回答「校园二手交易平台，三人团队，单机部署」。原任务继续，回答文字随模型生成逐段显示。架构图检查并保存成功后，右侧画布显示第一版。
2. 在一条带图的回答下点「用这张图提问」，输入「请求怎么走？」。助手解释选中的历史版本，右侧画布继续显示最新草稿。如果只说「解释第一版」，工作台会先请你选图，再继续同一次任务。
3. 你说「按项目的缓存规范给商品查询加 Redis，再解释改完的读写流程，订单链路保持原样」。这就是之前说的「复合任务」，也就是一句话里有几个动作。助手先查规范，再拿当前画布的临时副本修改，接着解释改好的版本。关键步骤都完成后，后端保存一次，聊天记录和画布显示同一次修改的结果。
4. 你可以拖动方框，刷新后回到上次保存的位置。点「保存为资产」会在项目侧栏留下一个可单独打开的成果。想从旧版继续改，可以先恢复到当前画布，也可以从那条历史消息开启新会话。

## 2. 文档里常见的说法

| 名称 | 在这里是什么意思 |
| --- | --- |
| 架构图（`Graph`） | 右侧画布里的方框和连线。`Graph` 是项目已有的数据名称，代码用它记录有哪些节点和连线 |
| 草稿、历史快照、资产 | 草稿是当前会话正在编辑的架构图。历史快照是某条消息当时保存的版本。资产是你主动保存到项目里的成果 |
| 一次任务（`Run`） | 助手处理一条请求的记录。后端用状态机管理它的进度，比如从执行中转为等待回答，你答完后转回执行中 |
| 流式输出（SSE） | 后端在生成过程中把阶段提示和回答文字陆续发给浏览器。重新连接时，浏览器可以继续接收原任务的内容 |
| 契约 | 项目原有的说法，指前后端约好传什么、返回什么。比如保存草稿时要带上开始编辑时的版本，后端据此判断草稿在这期间是否已保存过新版 |

代码里的字段沿用项目已有命名。具体数据格式以 [共享数据定义](../packages/shared/src/schemas) 为准。 [项目规范](../AGENTS.md)

## 3. 中途出错怎么办

| 遇到的情况 | 用户看到的结果 |
| --- | --- |
| 任务目标缺信息，或助手无法确认你说的是哪张图 | 暂停原任务并追问，你答完后继续 |
| 「按规范改图，再解释」的规范没找到，或改图失败 | 助手说明停在哪一步。当前草稿保持原样，依赖新版的解释标明未完成 |
| 改图后的解释超时 | 时间允许时，助手基于改好的临时图重试解释一次。本轮失败时保留已保存的文字与草稿，你可以重新发起任务 |
| 助手改图时，你先保存了新版画布 | 保留你的新版草稿。助手提示画布已更新，你可以基于新版再发起修改 |
| 浏览器断线 | 后台继续同一个任务。重连时优先补发还在缓冲中的事件，缓冲失效时用数据库里的记录恢复已保存文字和任务状态。每段文字只显示一次，模型继续原来那次执行 |
| 服务重启，正在执行的任务被打断 | 把中断的任务标记为失败，保留已经保存的文字和架构图，由你决定是否重试。已保存的待回答问题仍可以继续作答 |

改图提交前检查开始执行时的草稿版本。查看旧任务时，回答使用其助手消息保存的架构图快照。当前画布读取会话的最新草稿。 [Agent 接口的重连说明](<API文档/5. Agent.md#事件缓冲与恢复实现约束>)

## 4. 当前能用到哪里

- **本地账号与项目。** 工作台通过 `/api/mock` 注册、登录和续期。新账号有独立的空项目数据，项目、会话和任务保存在该账号的本地文件中。 [认证接口](<API文档/2. 认证.md#本地工作台>)
- **本地任务与画布。** 固定响应驱动的演示支持阶段提示、文字分段、卡片作答、同一任务续流和取消。事件缓冲可用于断线补发，缓冲失效时读取本地消息与任务快照。可以加载更早的消息并选择其中的架构图提问，也可以让助手给当前订单查询链路加缓存并解释流程。 [任务接口](<API文档/5. Agent.md#本地工作台>)
- **真实模型预览。** 开发环境开启 `ARCHFLOW_PREVIEW_AGENT=1` 并配置模型后，沿用同一套本地任务入口。解释等正文按模型输出流式传输，图或补丁完成校验后随任务结果发布。 [启动方式](../README.md#真实模型预览)
- **本地画布、资产与历史会话。** 画布支持拖拽、自动布局和自动保存。可以保存项目资产、从历史消息恢复架构图，也可以带着这条消息之前的对话和当时的图开启新会话。 [本地体验](../README.md#本地工作台体验)
- **本地项目资料。** 默认演示助手可按文件名和关键词查找当前项目里的 Markdown / TXT，回答下方显示原文引用。图片只检查能否读取，PDF 和 DOCX 只存储。真实模型预览尚未接入此检索。[AC7](#ac7-本地验证2026-11-24)
- **正式接口。** AC1 至 AC7 已在本机用 NestJS、PostgreSQL、Redis、MinIO 和受控测试模型完成验收。真实 Chat 和 1536 维向量模型待复验。 [正式联调记录](问题记录/2026-11-25-正式接口联调.md) · [待做清单](待做清单.md)

### AC1–AC7 的开发思路

| 验收项 | 怎么做、为什么 | 详细设计 |
| --- | --- | --- |
| AC1 登录和建项目 | 访问令牌放浏览器内存，刷新令牌由 `HttpOnly` Cookie 携带，后端在 Redis 管理有效期和轮转。同页请求共用一次刷新，多个标签页用 Web Locks 排队，避免争用同一枚刷新令牌。注册后展示空项目引导，建项目时自动创建首个会话。 | [登录与续期](数据流.md#流-1认证与无感刷新流-auth--token) · [创建项目](数据流.md#流-3新建项目与会话初始化) |
| AC2 流式对话和重连 | `POST` 提交消息，`GET` 订阅该任务的 SSE。后端独立执行任务并保存已生成的正文。浏览器断开后，有事件缓冲就补发，缓冲失效就从数据库恢复。需要追问时暂停原任务，答完沿用同一条助手消息。 | [对话与 SSE](数据流.md#流-4核心对话与-sse-流式推演-agent-run) |
| AC3 画图、改图和解释 | 先用当前会话、约束和图引用判断用户要做什么，缺信息就追问。简单任务直接调用对应能力。多步任务先按需查资料，再用临时图完成修改和解释，依赖步骤都成功后只保存一次。解释历史图时读取指定版本，画布继续显示当前草稿。 | [意图识别](系统架构与Agent编排设计.md#3-三层意图识别与有限重跑) · [两条执行路径](系统架构与Agent编排设计.md#4-主-agent-的两条执行路径) |
| AC4 编辑画布和保存 | 拖拽和自动布局先更新界面，停手后一起保存架构图和节点位置。前端带上开始编辑时的版本，后端发现已有新版就提示冲突，用户可读取先保存的画布。助手改图使用同一套版本检查。 | [草稿保存](数据流.md#流-6画布编辑与乐观锁防抖-draft-save) |
| AC5 保存为项目资产 | 打开保存弹窗时记录当前图和节点位置，确认后把它们另存为项目成果。侧栏打开资产时读取这份独立副本，所以继续编辑草稿后仍能查看原来的布局。 | [项目资产](数据流.md#流-7资产固化与懒加载-assets) |
| AC6 恢复旧图或开启新会话 | 恢复旧图会更新当前会话的画布，聊天记录照常保留。从历史开启新会话则复制所选消息及之前的对话，用当时的架构图初始化，两边以后各自保存。 | [历史版本与新会话](数据流.md#流-8历史分支与快照回溯-fork--snapshot) |
| AC7 根据资料回答 | 原件保存在 MinIO。Markdown 和 TXT 切片后写入 pgvector，助手只从当前项目内已入库且符合附件范围的原文取证，资料暂不可用时说明状态。图片当前检查格式和尺寸，PDF 和 DOCX 仅存储。 | [上传与处理](数据流.md#流-9文件上传与解析-files) · [何时查资料](系统架构与Agent编排设计.md#5-知识库在什么时候参与) |

## 5. 本地体验与正式验收

从 `pnpm dev:web` 启动本地工作台，用下列操作核对 AC1 至 AC7 的本地流程。账号、消息、任务、草稿、资产和上传资料保存在本地文件中。 [启动方式](../README.md#本地工作台体验)

1. 注册并登录新账号，从空态创建项目和会话。刷新工作台后从项目树打开原会话。
2. 发送「画个架构图」，在卡片选一项。观察卡片变为已回答，原助手消息接着显示文字和架构图。
3. 流式显示期间短暂断网，再连接时核对是否沿用原任务且文字只出现一次。另发一条任务并取消，检查上次保存的草稿和再次发送入口。
4. 先后生成两张不同的图，再重启 Web 服务。打开第一张图对应的历史消息，对照右侧当前画布。生成中重启时，检查已保存文字是否还在，以及能否重新发送。
5. 先画订单服务架构图，然后发送「给订单查询加缓存，再解释改完的流程」。选择第一张图提问，检查回答列出的节点和连线来自首版，右侧画布仍显示查询缓存。输入「解释第一版」后也可按提示选图并继续回答。需要翻看旧图时，点击聊天记录顶部的「加载更早的消息」。
6. 拖动节点，等「已保存」后刷新。用「自动布局」重新排列后，再等保存并刷新。用两个标签页打开同一会话，在一页保存后用另一页的旧草稿拖动节点，看到冲突时点击「读取最新画布」。
7. 拖动节点后，点「导出 → 保存为项目资产」，输入名称并保存。从项目侧栏的「资产库」打开这份资产。再调整草稿并刷新，核对资产仍显示保存时的图和节点位置。
8. 在带图旧消息的「…」菜单点「恢复快照」，确认后核对右侧画布和原有聊天记录。再用「从此开启新会话」创建独立会话。分别调整两个会话的画布并刷新，核对各自的架构图和节点位置。
9. 准备一份内容为「缓存 TTL 为 47 秒。」的 `缓存规范.md`，上传到一个项目。文件变成「可引用」后，在该项目的会话中问「根据《缓存规范.md》，缓存 TTL 是多少？」。核对「参考资料」中的原文，再到另一个项目重复提问，确认不引用前一个项目的文件。

## 6. 原讨论和进一步阅读

- 一个聊天入口由后端选执行方式。第一层就使用必要的聊天历史、已确认条件与明确的架构图引用。原设想是先规则、再比较相似问法、最后由模型改写后重新识别。改写后直接用模型的判断，以及必要时最多复检一次前两层，都保留为评测选项。 [系统设计第 2 至 4 节](系统架构与Agent编排设计.md#2-从用户输入到编排上下文)
- 标题可在任务目标明确后生成，保留用户手动设置的标题。推荐问题优先依据实际提交的回答和架构图。两项辅助内容可以在主结果结束后独立写回。 [任务、画布和辅助结果](系统架构与Agent编排设计.md#6-run画布与产品结果)
- WeKnora 由助手配置选择模式，快速问答的意图标签决定是否检索，智能推理中的模型看完工具结果再选下一步。ArchFlow 可以借鉴工具结果交回模型、证据引用和断线续传的做法。 [WeKnora 源码笔记](WeKnora-Agent与RAG编排.md)
