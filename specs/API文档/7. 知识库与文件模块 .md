# 7. 项目文件与图数据

> 当前文件上传、处理、检索和下载尚未实现。文件记录字段来自 `knowledge.schema.ts`，图定义来自 `common.schema.ts`。

## 7.1 上传文件

```http
POST /api/v1/projects/:projectId/files
Content-Type: multipart/form-data
```

表单字段为 `file`，检查项目所有者后保存原文件和记录。允许类型如下，未知类型返回 `415 FILE_TYPE_UNSUPPORTED`：

| 扩展名                           | 业务分类 | 第一版处理                 |
| -------------------------------- | -------- | -------------------------- |
| `.md`、`.markdown`、`.txt`       | 文本     | 提取、分段、向量化后可检索 |
| `.png`、`.jpg`、`.jpeg`、`.webp` | 图片     | 生成文字描述并入库后可检索 |
| `.pdf`                           | PDF      | 仅保存，不读取内容         |
| `.docx`                          | DOCX     | 仅保存，不读取内容         |

大小初始上限为 20MB，超出为 `413 FILE_TOO_LARGE`；文件数、解析超时和类型真实性验证需 P0-17 落实到服务端配置/校验，不能只信扩展名或浏览器 `Content-Type`。

成功返回 `201` 与 `FileMeta`，只说明原文件与记录已保存，不保证处理完成：

```json
{
  "id": "fil_1",
  "fileName": "需求.md",
  "fileType": "text",
  "mimeType": "text/markdown",
  "sizeBytes": 20480,
  "status": "processing",
  "errorMessage": null,
  "createdAt": "2026-11-13T16:00:00+08:00"
}
```

文本/图片处理和片段入库完成后才进入 `ready`，失败进入 `failed`。PDF/DOCX 直接 `stored`，不参与后续处理或引用。处理发生在 Node.js 应用内，第一版不接消息队列。

## 7.2 获取文件列表

```http
GET /api/v1/projects/:projectId/files?limit=20&status=processing
```

请求使用 `FileListQuery`，响应为 `PageSchema(FileMeta)`。文件状态过滤使用共享定义。列表与项目目录都不返回内部存储地址。

## 7.3 文件详情与批量状态

```http
GET /api/v1/files/:fileId
GET /api/v1/projects/:projectId/files/status?ids=fil_1,fil_2
```

详情返回 `FileMeta`；批量查询使用 `FileIdsQuery`，返回 `FileStatusResult`。即使客户端提供文件 ID，服务端也要检查其所属项目和用户，不能跨项目查询。

上传后可从约 2 秒间隔开始查询状态，逐渐延长到最多 60 秒间隔。只对处理中状态继续查询；可用、失败、仅存储或离开页面后停止。`failed` 显示安全错误提示，不返回解析库堆栈或内部路径。

## 7.4 下载原文件

```http
GET /api/v1/files/:fileId/content
Authorization: Bearer <accessToken>
```

通过鉴权 API 转发文件，成功响应不使用 JSON 包装。普通下载返回 200，范围请求支持 206，并设置媒体类型、下载文件名、长度、ETag 和 `X-Trace-Id`。

不向前端下发 MinIO 内部路径或签名直链，因此没有单独的“下载链接 15 分钟过期”规则；请求权限由访问凭证控制。API 会承担文件传输流量，后续需要时再评估分发方案。

## 7.5 删除文件

```http
DELETE /api/v1/projects/:projectId/files/:fileId
```

成功返回 204 与 `X-Trace-Id`。删除记录、检索片段及 MinIO 对象；处理中任务不能在删除后重新写回内容。数据库与对象存储无法单凭外键保持一致，清理失败的补偿见[Q-08](../待确认问题.md#q-08-删除行为与对象存储清理)。

## 7.6 图数据

图供生成任务、草稿和命名方案共用。`GraphNode` 表达标识、类型、标签和说明，`GraphEdge` 表达起点、终点及标签；`Graph` 是容器，`GraphInput` 额外检查请求合法性。

节点类别、字段格式、数量、字节和深度限制全部查共享定义，不在此另维护一份数值表。输入拒绝未知字段、重复节点/边 ID、不存在的起终点和自身连接；不等于已检测所有多节点环路。

体积超限为 `413 GRAPH_TOO_LARGE`，其他结构与引用问题为 `422 GRAPH_INVALID`。模型生成图后，程序重映射节点 ID 时同步更新边，前端计算布局。SSE 图事件名称是 `graph`。

当前 `GraphNode` 不保存坐标，但产品要求保留用户布局，需先定义[Q-01](../待确认问题.md#q-01-拖拽位置如何保存)的独立布局方案。`LooseGraph` 只用于旧模拟图读取，不能作为新写入结构。
