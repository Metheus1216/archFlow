# ArchFlow 待做清单

> 状态：2026-11-12。
> 用途：把架构决策拆成可执行事项。优先级按“是否阻塞 MVP 主链路”划分，不按时间周排期。
> 每项完成后，在“状态”列改 `✅`，并在右侧补验收证据（测试、指标、文档链接）。

## 优先级定义

- **P0**：阻塞 MVP 主链路；不做就无法端到端跑通。
- **P1**：不阻塞主链路，但直接影响质量、安全或可评估性。
- **P2**：post-MVP 扩展；有明确触发条件再做。

状态：`⬜ 未开始` / `🟡 进行中` / `✅ 完成` / `⏸ 暂缓`

### P0 执行顺序

1. P0-01 契约先定，避免后面反复改类型。
2. P0-02 / P0-10 一起做，所有请求从第一天就有 traceId 和统一错误。
3. P0-03 → P0-04 → P0-05，先把 Agent 主链路跑通。
4. P0-06 / P0-07 接入流式和 HITL。
5. P0-08 / P0-09 接入 RAG 与模型。
6. P0-11 / P0-12 贯穿始终，不要留到最后。

## 明确不在清单内

以下事项属于 MVP 红线或已明确不做，不要因为“架构完整”而提前实现：

- PDF / DOCX 解析（post-MVP 才由 Go 服务承担）。
- BullMQ / Redis 队列。
- 完整微服务拆分、服务网格、API Gateway。
- WebSocket / Yjs 多人协作。
- LangChain / LangGraph / Vercel AI SDK。
- MCP、reasoner、rerank、混合检索在 MVP 中落地。
- Skill 插件市场、多 Agent 编排、Skill 全局可变开关。
- BYOK / 自定义 Base URL；当前只考虑平台预设模型，不与 P2-10 混做。

## 完成定义

一项任务标记 `✅` 前，至少满足：

1. 契约先改 `packages/shared`，类型检查通过。
2. 有对应测试或可复现的验收步骤。
3. 错误路径有明确返回码，不泄露内部信息。
4. 关键路径有 traceId 和日志。
5. 文档中的契约与代码一致；若不一致，先改文档或先改代码，不允许长期漂移。
